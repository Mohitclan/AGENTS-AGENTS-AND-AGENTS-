# lead-generator memory

What lead-generator has learned. Claude Code loads the first 200 lines into every lead-generator run.

- 2026-10-30 · Before recording a missing video as an observed_gap, check each launch listing's media section, the company's YouTube presence, the README and docs, and pages beyond the homepage. Name what was checked, one URL each. A homepage with no video is not a gap. (source: outputs/reviews/T-20261030-06-r1.md · by: coordinator)
- 2026-10-30 · A failed lookup is not 'not found'. Say which sources failed and which were tried, and look up listing sites, Hacker News, and the public LinkedIn company page before calling size, location or launch history unknown. (source: outputs/reviews/T-20261030-06-r2.md · by: coordinator)
- 2026-10-30 · Compare what a lead sells with the competitor file before scoring, indirect categories included. Comparison posts naming a listed competitor are a signal to flag it. (source: outputs/reviews/T-20261030-07-r1.md · by: coordinator)
- 2026-11-01 · Mark a segment test fail only on positive evidence with its source; if nothing was seen it is unknown. Use only pass, fail or unknown, and let missing data keep a row open rather than reject it. Check about, terms, privacy and changelog pages before writing 'not stated'. (source: outputs/reviews/T-20261101-03-r1.md · by: coordinator)
- 2026-11-01 · When a page or founder post mentions a clip or video, follow it to its target, including the founder's launch post, before leaving test 6 unknown. A maker name on a listing is not a founder: confirm the role, and record conflicting sources side by side. (source: outputs/reviews/T-20261101-03-r2.md · by: coordinator)
- 2026-11-01 · Recount every total in the notes from the final table last. A summary line must agree with the rows, and a reason given for skipping a check must be true of every row it covers. (source: outputs/reviews/T-20261101-03-r2.md · by: coordinator)
- 2026-11-01 · Try a route before saying it can't do something. A wrong 'the mirror gives no timelines' hid the decisive evidence on both open rows; api.fxtwitter.com/2/profile/<handle>/statuses gives timelines, one fetch per product and maker account. (source: outputs/reviews/T-20261101-05-r1.md · by: coordinator)
- 2026-11-01 · Scrutinise the rows you keep open hardest: a claim of absence ('no video', 'nothing links') decides those rows, and five of six failed spot-checks here were absences. Retry a page that errored once before listing it as failed. (source: outputs/reviews/T-20261101-05-r1.md · by: coordinator)
- 2026-11-01 · Quote a source on someone's job or role instead of summarising it, and apply one rule to every row; when a rule isn't settled, flag it rather than use it as a reason on one row and a caveat on another. Reword every row a ruling touches, rejected ones too. (source: outputs/reviews/T-20261101-05-r2.md · by: coordinator)
- 2026-11-01 · Before writing 'no handle known', check the maker's GitHub profile and portfolio links, and run a next-action list against the review's fix list so no step for a person gets dropped. (source: outputs/reviews/T-20261101-05-r2.md · by: coordinator)
