Before listing commands for a person to run, open the scripts behind them. Check prerequisites (a build output, a config, a dependency that isn't declared).

**Why:** In T-20261101-01 r1 I listed `typecheck`, `lint` and `check:site` from package.json only. r2 found `check:site` exits 1 without `next build`, and `next lint` has no ESLint installed or configured. The developer copied my list, so my error reached the write-up.

**How to apply:** Read the first lines of each script and grep the dependency in package.json and the lockfile. When a heavily weighted criterion can't be met in the session, give the score ceiling and say whether to ask the human before spending the last revision, so it can carry real results. Also check "result nobody saw" wording: "still works" from code reading must say it wasn't run.

**Attribute and dry-run with archives.** `git archive <commit>` and `<commit>^` into the scratchpad. Run the suite on both to tell a pre-existing failure from a new one. In T-20261103-03, the `control.test.mjs` EBUSY cleanup failure (Windows) failed on main too. Run write-only generators (`fallbacks.mjs sync`) there and diff. Also cross the new script with the parent's files.

**New lint checks (T-20261103-04).** To prove "warn-only", diff FAIL lines and exit codes, parent against commit, over the real corpus, then flip each new `warn` to `fail` in a scratch copy and run the tests. Probe same-line overlap with the existing fail checks (`checkClaims`, `hard`). Probe recall on the copy type the check targets (e.g. testimonial layouts on seo/social) when the corpus has none of it. In r2, a next-line "dash + Name" regex accepted `- ` and so read markdown list items as attributions in every type; the corpus was silent. Probe each widened regex against markdown structure (bullets, callouts, tables), and grep the first-pass self-review for echoes of the fixed facts.

**Mutation-probe safety tests.** For an agent-tools allowlist test, probe the shapes the regex skips. An omitted `tools:` line inherits every MCP tool. Also try `mcp__*` and weakened rule wording.

**Matcher changes: trace the writer's normalisation and every other reader.** In T-20261103-09a, `suppress` strips a URL to its host, so a LinkedIn opt-out becomes `linkedin.com`. A wider gate match turned that into a Stop on every LinkedIn lead, and on main it blocked nothing (a hard rule 7 gap). Grep every reader of the same list (`send-email.mjs` had a third rule). Grep the unchanged sections of the same doc for the old meaning. A self-review "one answer: fixed" missed one.

**Normaliser probes (T-20261103-11).** For any "store it canonical" fix, feed the writer odd but real inputs and read what it stores: `mailto:` prefixes, hosts that are `m.`/`mobile.`/`www.` plus a TLD (`mobile.de` became `de`), query-identified pages (`profile.php?id=`), one-segment reserved paths, free-mail domains, and hand-edited forms the CLI would refuse (`https://www.linkedin.com/` matched everyone). Also ask whether the interim instructions create the "legacy" entries the fix ignores. In r2 I found what r1 missed: a prefix matcher needs probing in both directions. An entry *below* the contact (`x.com/h/status/1`, `linkedin.com/messaging/thread/…`, `/in/x/overlay/contact-info`) covered no one and `check` was silent. Feed the writer the URL an opt-out actually arrives at (reply, DM thread), then run the CLI on a real lead and read "N disqualified". Also try `.acme.com` and `*.acme.com`.

**Probe every syntax the real parser accepts, not just the one the repo uses.** In T-20261103-03 r2, `_agents.mjs` kept scalars raw, so a YAML flow list `tools: [mcp__hubspot__x, ...]` or a quoted string with the bad entry first passed every case on `sales.md`. I missed this in r1. Put the bad entry first and last. Check the docs on empty values: an empty `tools` list gives no tools; only an omitted one inherits. After a strip-brackets/quotes fix (r3), also probe multi-line flow lists and `>-` block scalars (the line parser skips continuation lines; both slipped through) and a `# comment` (false positive). A flaky file-level failure adds one to the test total (284/1 vs 283/0), so a different total isn't a discrepancy.

**Metric scripts (T-20261103-08).** Diff every label or set member against the spec the coordinator cites, not the file the write-up cites (the definition had moved to a README brief; 3 labels and a whole count were off). Mutate each set member and each filter one at a time: label and `mode === 'live'` reply mutants survived 23 green tests. Prove read-only by hashing a scratch copy of `ops/ pipeline/ outputs/` before and after every command with `--root`; a whole-tree `find -newer` is slow and noisy with other agents writing. A `git archive` base needs `node_modules` copied in. Check file-name parsers against the live folder (a `T-…-09a` ID appeared mid-review) and whether a missing round is provable from a higher round's name. On r2, keep the mutant runner script in the scratchpad (string replace, assert one match, control run) and add mutants for every new branch: 3 of 24 new ones survived (unrecognised label, missing date, warning). Test "no deviation" claims against each list in the brief: bounce sat in the brief's "does not count" (in-n) list but was held out of n.
