# Demo script

## A 25-minute live demo

| Minutes | Part | What happens |
|---|---|---|
| 0-3 | Set-up | Agree the goal of the call and the time. "By the end you'll know whether this solves X." |
| 3-8 | Discovery | Confirm the pains from their evidence; ask what they use today and what "good" looks like |
| 8-20 | Three workflows | Each one solves a pain they just named, in their language, with sample data that looks like theirs |
| 20-23 | Questions | Answer honestly; note anything to follow up |
| 23-25 | Next step | Ask for one concrete next step: a trial, a call with the buyer, a pilot |

Show the outcome first, then how you got there. Skip setup screens and settings unless they ask.

## A 2-3 minute recorded demo

Scene by scene: the problem in one sentence (10 s), the product solving it end to end (90 s), one proof point (15 s), the call to action (10 s). Write the narration and the on-screen action for each scene.

## Earn the demo

Hold a live demo only when you know the named pain, who's attending, what "good" looks like to them and the next step you'd agree. If any is missing, run a short discovery call first.

For a pilot, the person who decides signs off the success criteria before anything is built, and we say up front which criterion we expect to miss. Use made-up sample data only, never another customer's. Give every published demo an owner and an expiry date.

## Before any demo

- Every feature you show is `live` in the confirmed fact sheet. Label beta features as beta; never show planned ones as real.
- Walk through the flow on the live product or in the code the day before, and note anything that doesn't match the script.
- The demo account exists, its data is reset, and its login lives in the password manager, never in the plan.

## After

A recap email the same day: what they said, what you showed, what you promised, the agreed next step.
