### 3. Replacement wording: "one repository" holds; "the same code" does not

- **"From one repository": supported.** Evidence 5 holds, and the live home page agrees ("Connect GitHub, pick a repository, and get the teaser, the walkthrough, and the technical and sales docs"). No new joined claim.
- **"From the same code" (row 2): not supported, and it is a new joined claim.** Evidence 4 says no code ties the two to one commit, and the proposal's open question says no copy should say "same commit". The code goes further than "not established":
  - A video takes a user-chosen `branch` (`src/api/teaser.ts:365`), while documents use the default branch or a push to main.
  - A revision deliberately runs against the old commit (`TeaserOrchestrator.ts:269-271`).

  So the two can differ by design. "Same code" reads as the same snapshot, which is the claim the proposal rules out. Line 36's "equally supported" is wrong, and row 2 also contradicts line 20, which says the replacement "says 'one repository' instead".
- **"Of the documents" / "of the PDFs": justified, and disclosed.** The site and code both support it: `site.ts:252`, `:291`, `:414` and `:487`, `pricing.ts:52`, and the live home page's "Rewritten when the code changes" under Documents. It goes beyond "change only that idea", but lines 20 and 136 say so plainly and give the human the choice. Without it the old implied claim stays, so I accept it. One practical gap: each Proposed line combines both changes, with no ready wording for taking only the first.
- **Row 3 parenthetical: not resolved (fix 3).** After the edit, line 49 reads "regeneration of the PDFs built into the product (RepoClip can **also** remake video on release, **but** through its API...)". "Also ... but" only works if MotionRepo remakes video too. Line 42 says this "now reads accurately". It does not: the scoping removes the claim in one clause and the parenthetical puts it back.
