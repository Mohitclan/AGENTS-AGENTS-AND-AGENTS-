### Fix 5: is the departure from claim-check rule 2 sound?

**Yes, and it's stated clearly enough to follow.** My reasons:

1. **The frontmatter is the right anchor.** CLAUDE.md says every knowledge file has its status "in its frontmatter", and `kb.mjs status` lists both MotionRepo files as confirmed (cited in `knowledge/proposals/2026-11-03-motionrepo-stale-status-lines.md`).
2. **It never picks the riskier side.** The rule uses the frontmatter and also marks `[UNCONFIRMED]` every fact the body calls unconfirmed, so a fact flagged in either place never appears as plain fact. Here that means:
   - every MotionRepo product fact is marked (product line 20 says "All of this file is `proposed`");
   - competitor facts stay usable (competitor lines 17 and 19 qualify only "our" product facts);
   - `directory-listing` line 35 then blocks submitting any listing until the stale lines are removed.
   That's conservative, and it gives the same answer in all three skills.
3. **The departure is narrow and still flags.** It drops only "stop". It keeps "flag" (a handoff to `knowledge-base`) and applies only when frontmatter and body disagree about status. Claim-check rule 2 is written for "two files" that disagree. This is one file disagreeing with itself, so the skills are filling a gap rather than overruling the rule.
4. **The fix the handoff asks for is already in progress.** Proposal T-20261103-10 (`knowledge/proposals/2026-11-03-motionrepo-stale-status-lines.md`) removes the stale lines. Once a person applies and re-confirms it, the rule stops triggering for MotionRepo.

- "each fact the body calls unconfirmed" should state that a whole-file line such as product line 20 covers every fact.
