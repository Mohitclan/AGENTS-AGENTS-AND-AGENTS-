## Claims verified

1. **Contrast figures in the write-up.** I computed them with the WCAG formula: ink/paper 14.80, green/paper 6.92, muted/paper 6.40, ink/mustard 7.98, vermilion/paper 3.48, #b3321a/paper 5.28. All match the write-up. Vermilion at 3.48 is only used for large numerals, which need 3:1, so that's fine. **The check it missed:** `button.quiet:hover` sets a mustard background but keeps the #b3321a text, which is **2.85:1** (fix 1). Muted text on the "seen" fill #f2dfa8 is 5.69, which passes.
2. **"Animations therefore keep running across the 3 s refresh."** I appended a probe to the `--once` page and ran it in headless Chrome at 1440 px. It set the researcher to `work`, waited, called the page's own `setTop()` with the hero HTML plus one changed count, then read the state again:
   - SMIL: `svg.getCurrentTime()` was 3.88 s before and 3.88 s after, then 4.88 s one second later, on the same `<svg>` element. **Supported.**
   - Leaf text was patched ("5 tasks"), `data-st` was kept, and there is one `#map` and one `#p-hatch` in the document, so no duplicate IDs.
   - CSS: the `halo` animation on the working agent was a **new Animation object at currentTime 0** afterwards. `setTop` detaches `#map` (`old.remove()`) and re-attaches it, which cancels CSS animations. **Not supported for CSS.** In live mode, when the HTML changes on most refreshes, the halo pulse and the spoke flow will restart. Fix 5.
3. **"SVG text is about 10 px at 1100 px width."** Measured in Chrome: a 1178 px viewport gives an SVG 1069 px wide, a 0.80 scale, so 11 px map text renders at about 8.8 px and the 10 px "BACKUP IN" at 8.0 px. By the same CSS, a 1080 px viewport gives about 994 px, a 0.75 scale, so 7.5 to 8.2 px. **Not supported.** Fix 4.
4. **"Not touched: server, auth, `act`, `handle`, CSP."** Supported by the hunk list above.
5. **"213 tests, 213 pass."** Supported, by running them.
6. **Rollback "`git checkout project-progress` returns to the old page".** Supported: `project-progress` is at 6c70a58, the parent commit, and `main` has no change to `scripts/dashboard.mjs` relative to it.
7. **`activeAgents` reads what `recentSteps` produces.** Supported: `describeTool` (`dashboard.mjs:115-118`) writes `Handed work to <subagent_type>` and `Wrote <root-relative path>`, which match the regexes at `dashboard.mjs:159`.

## Fixes (REVISE)

1. **[Constraint breach: WCAG AA]** `scripts/dashboard.mjs`, STYLE, the rule `button.quiet:hover{background:var(--mustard);box-shadow:none}`. #b3321a text on mustard #e2a527 is 2.85:1, under the 4.5:1 needed for small text. It affects "Sign out", "Pause motion" and every other `.quiet` button. Add `color:var(--ink)` to that rule (7.98:1). A one-line test that the hover rule sets the ink colour would stop it coming back.
2. **[Visual defect]** `scripts/dashboard-art.mjs:293`, the `CHECKPOINT` kick text at `x=evalPos[0]+22`, `y=CY-NH/2-22`. It runs from about x 1037 to 1115 at y≈328-336, while the gate bust (`:246`, body at x 1098-1146, y 313-338) covers the end. Move the label left, for example `x=evalPos[0]-NW/2` with a start anchor, or above the double frame, so the whole word shows.
3. **[Visual defect]** `scripts/dashboard-art.mjs:112` (`.nm` at `x="49"`) with `NW = 150` at `:34`. At 11.5 px mono, 14-character names ("LEAD-GENERATOR", "KNOWLEDGE-BASE") end at about x 147, but the right notch cuts in to x 144 and the border is at 148.9. Widen `NW` (for example to 164), or shrink `.nm` for long names. Check the ring spacing and the stub positions again afterwards.
4. **[Visual defect: readability] plus a write-up correction** `scripts/dashboard-art.mjs:497`, `@media (max-width:1079px)`. Between 1080 and about 1250 px the map text is 7.5 to 8.8 px. Raise the breakpoint where the route list takes over (for example to 1279px), or enlarge the SVG text. Then correct the line in `outputs/dev/T-20261102-01.md` under "What I could not check" ("SVG text is about 10 px at 1100 px width") to the measured figure.
5. **[Partial constraint breach: refresh keeps the animation] plus a write-up correction** `scripts/dashboard-art.mjs:579-580`, `setTop`. `old.remove()` then `fresh.replaceWith(old)` keeps the SMIL clock but restarts every CSS animation in the map: the working halo (`:440`), the spoke flow (`:447`) and the route-list blip (`:476`). It happens on each refresh where the HTML changed, which is most refreshes during a live run. Keep `#map` attached instead. For example, parse the new top HTML into a `<template>`, run `patchMap(old, template's #map)`, and replace only the hero nodes that come before the map. Then update "Live refresh" in the write-up, which now says "Animations therefore keep running across the 3 s refresh", to match what was tested. If the developer keeps the current code, the write-up must say plainly that CSS pulses restart on changed refreshes.
6. **[Optional, accessibility polish]** `scripts/dashboard-art.mjs:274`. `aria-labelledby="map-t map-d"` makes the whole 600-character description the image's name. Use `aria-labelledby="map-t" aria-describedby="map-d"`, and update the regex in `scripts/tests/dashboard.test.mjs` (the `role="img"` assertion).

Fixes 2-4 are visual. Fix 1 is a hard-constraint breach. Fix 5 is partly a constraint breach (the refresh must not restart the animation) and partly a write-up accuracy problem. If fixes 1-5 are made and the tests still pass, I expect this to reach about 88.
