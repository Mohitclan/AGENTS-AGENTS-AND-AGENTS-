## The gap (why ESCALATE)

**On a shared path host, `suppress` stores whatever page you give it. If that page sits below the person's profile, the entry covers nobody. Nothing warns.**

Probed in a scratch copy (`git archive fa7fffb` plus the real `leads.jsonl`), using SpaceWise (`L-64817c69`, contact `https://x.com/_ojas_13`):

| Step | Result |
|---|---|
| `suppress "https://x.com/_ojas_13/status/1850000000000000000" "replied stop on X"` | `Suppressed https://x.com/_ojas_13/status/1850000000000000000.`, exit 0, **no lead disqualified** |
| `check` | `OK: 8 lead(s), no problems found.`, exit 0 |
| `gate --product motionrepo` | SpaceWise still **Conditional**, no suppression reason |
| `set-status L-64817c69 drafted` | `Set 1 lead(s) to drafted.`, exit 0 |
| Control: `suppress "https://x.com/_ojas_13"` | `1 open lead(s) disqualified.` |

The same happens for Cool Analytics with `https://www.linkedin.com/in/mdanassaif/overlay/contact-info/`, which gives no Stop. Other inputs that are stored as given and cover nobody (`suppressionProblem` returns `""` for each, so `check` stays silent):

- `https://www.linkedin.com/messaging/thread/2-abc==/`. This is where a LinkedIn opt-out arrives.
- `https://www.linkedin.com/in/<name>/details/contact-info/`, `/recent-activity/all/`
- `https://www.linkedin.com/comm/in/<name>` (the form LinkedIn uses in emailed links)
- `https://www.linkedin.com/posts/<slug>`, `https://www.linkedin.com/jobs/view/123`
- `https://twitter.com/<handle>/status/1?s=20`, `https://x.com/<handle>/with_replies`
- `https://github.com/<name>/<repo>`, `https://www.youtube.com/@<name>/videos`, `https://www.instagram.com/direct/t/1234/`

Two domain forms also cover nobody and pass `check`: `.acme.com` and `*.acme.com`. Each is stored literally and matches neither `lee@acme.com` nor `app.acme.com`.

This also makes the write-up's fix-4 claim false (`T-20261103-11.md:122`): "`suppress` never prints 'Suppressed' for an entry that covers no one".

**What would close it.** This is about one function plus tests, but it needs a developer round:

1. In `readSuppression` (`_shared.mjs`), for a `PROFILE_PATH_HOSTS` URL, store only the profile part of the path:
   - the first segment (`x.com/<handle>`, `github.com/<name>`);
   - the first two segments when the first is in `NEEDS_NAME` or the host has `MIN_PATH_SEGMENTS` (`linkedin.com/in/<name>`);
   - `facebook.com/people/<name>/<id>`, and `profile.php?id=`.
2. Refuse first segments that are activity or messaging pages, not profiles: `messaging`, `posts`, `pulse`, `jobs`, `comm`, `direct`, `p`, `reel`, `status`. Use the existing "does not name one person" message.
3. Have `suppressionProblem` flag a stored `url` entry whose path is longer than the profile part, so `check` catches hand-written ones too.
4. Refuse a domain that starts with `.` or `*`.
5. Cheap extra signal: when `suppress` disqualifies 0 leads, print it ("0 open leads matched: check this is the person's own profile URL or address").
6. Add tests: a status URL, a LinkedIn messaging thread and a `/details/contact-info` URL are each stored as (or refused in favour of) the profile, and the lead becomes a Stop.

**If the human merges without that round:** add a human check and a coordinator assumption. For X and LinkedIn opt-outs, record only the bare profile URL (`https://x.com/<handle>`, `https://linkedin.com/in/<name>`), never the URL of a post, reply or message. Then confirm that `suppress` printed `1 open lead(s) disqualified` for a known lead.
