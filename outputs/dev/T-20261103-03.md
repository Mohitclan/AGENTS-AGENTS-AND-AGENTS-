# T-20261103-03: limit HubSpot tools to ten read-only names

Branch: `agent/T-20261103-03`. Approval: A-20261103-01 ("yes"). Source: Finding F1 in `outputs/research/2026-11-03-gtm-survey-b-skills-connectors.md`, verified in `outputs/reviews/T-20261103-02-r2.md`.

## Problem and root cause

Four agents (`lead-generator`, `sales`, `lead-generator-fallback`, `sales-fallback`) had `mcp__hubspot__*` in `tools:`. That is every HubSpot MCP tool, including the 11 that write (`manage_crm_objects`, `manage_segment`, `manage_custom_properties`, `manage_custom_pipelines`, `manage_campaign_objects`, `manage_marketing_email`, `manage_landing_page`, `manage_website_page`, `manage_blog_post`, `manage_aeo_prompts`, `manage_aeo_recommendations`).

Evidence: `grep -rn "mcp__hubspot" .claude/agents` showed the wildcard on line 4 of all four files. `.claude/settings.json` has no `mcp` text, and its PreToolUse matchers cover only `Write|Edit|MultiEdit|Read|Bash` and `Agent`, so no hook runs on `mcp__` tools (survey F1, lines 57-63). Hard rule 1 (drafts only) was enforced only by prose.

## What changed

The new HubSpot part of `tools:`, identical in all four files (the rest of each line is untouched):

```
mcp__hubspot__get_user_details, mcp__hubspot__get_organization_details, mcp__hubspot__discover_hubspot_schema, mcp__hubspot__search_crm_objects, mcp__hubspot__get_crm_objects, mcp__hubspot__query_crm_data, mcp__hubspot__search_properties, mcp__hubspot__get_properties, mcp__hubspot__search_owners, mcp__hubspot__tool_guidance
```

These are the survey's nine read-only tools plus `tool_guidance`, which r2 (line 89) shows is read-only and recommended before `query_crm_data`. Names were checked against the survey's HubSpot row (line 38) and r2 (lines 84 and 178-180).

### Fallbacks and `scripts/fallbacks.mjs`

I read the script before running anything. `check` compares each fallback's `tools` (the main agent's tools minus `Agent`), `model`, `color`, `fallback_for` and skills. `sync` rewrites each fallback's whole file, body included, from a template. So the fallback tools had to mirror the new list, and a rule typed by hand into a fallback body would be erased by the next `sync`.

Fix: `scripts/fallbacks.mjs` now adds the HubSpot rule as item 7 of the generated body, only when the main agent's tools contain `mcp__hubspot__`. Other fallbacks are generated exactly as before.

Sequence: after editing the two primaries, `check` failed with 2 problems (the two fallbacks' tools). `sync` then rewrote all ten fallbacks, and `git diff --stat .claude/agents` shows only the two intended fallback files changed, so the other eight came out identical. `check` then printed `OK: 10 fallback agent(s) match their main agents.`

Files changed: the four agent files, `scripts/fallbacks.mjs` (+8/-1), and the new `scripts/tests/agent-tools.test.mjs`.

## The test

`scripts/tests/agent-tools.test.mjs` is picked up by `scripts/test.mjs` automatically. Four cases:

1. Every agent file under `.claude/agents/` (not only the four) lists no `mcp__hubspot__` wildcard and no HubSpot tool outside the ten.
2. The four agents list exactly the ten.
3. The check function itself rejects a wildcard, a write tool (`manage_crm_objects`), a misspelt name, an `mcp__*` entry and a missing or empty `tools:` line, and accepts a valid one. This stops case 1 passing by being vacuous. (Revision 1 added the last two.)
4. Every agent that has HubSpot tools carries "HubSpot is read-only for you" and "Never create, update, delete, send or publish", and does not contain "unless the human approves". (Revision 1 added the last part.)

It fails before the fix: with the `.claude/agents` edits stashed, `node --test scripts/tests/agent-tools.test.mjs` gave `# pass 1`, `# fail 3` (cases 1, 2 and 4 failed; case 3 passes by design). After: `# pass 4`, `# fail 0`.

## Risks

- If the live server names a tool differently (for example `tool_guidance`), the agent silently loses that tool and lookups may fail. This is safer than the wildcard.
- The guard is still instruction-level. The new test catches, in any file under `.claude/agents/`: a `mcp__hubspot__*` or other `mcp__*` wildcard, a HubSpot tool outside the ten, and a missing or empty `tools:` line (which would inherit every tool). It does not catch other MCP servers named without a wildcard, a bare `mcp__hubspot` entry, or a rule reworded in a way that avoids the two phrases it checks. It runs when someone runs the suite, not at call time, and no hook runs on `mcp__` tools.
- Forked subagents, and the main session if it has HubSpot connected, are not limited by these `tools:` lists: per the Claude Code subagent docs (as the reviewer fetched them), forks receive the main conversation's exact tool pool. Only a PreToolUse hook would limit them. That hook is still a human decision.
- With no write tool available, an approved CRM change has to be done by a person in HubSpot.
- `query_crm_data` and `search_crm_objects` can return contact personal data. Hard rule 3 applies.
- The template change in `fallbacks.mjs` affects every future `sync`, but only for agents with HubSpot tools.
