# T-20261102-01: redesign of the team page

Branch `agent/T-20261102-01` (local only, not pushed). Port used for checks: 4398 (a throwaway run that ended itself). See "Stray server" below for 4399.

## Design direction
- **Idea:** a print-shop control room (risograph). Warm paper with a halftone dot texture, ink rules, offset-block shadows, ticket and stamp shapes. Square corners everywhere; no rounded cards, no pills, no blurred shadows, no gradients except hazard stripes and dot patterns.
- **Fonts (Google Fonts, `display=swap`):** Big Shoulders Display for headings and big numerals, Newsreader for body text, IBM Plex Mono for labels, IDs and data. Atkinson Hyperlegible and Bricolage Grotesque are gone. No `system-ui` anywhere.
- **Palette:** paper #f3ecdf, card #faf5ea, ink #1c1a15, vermilion #e0482d, deep green #0f5a4a, mustard #e2a527. No purple, no neon, no glass. Contrast (calculated by hand): ink on paper about 15:1, green on paper 6.9:1, muted #5a5446 on paper 6.4:1, ink on mustard 8:1. Plain vermilion on paper is only 3.5:1, so it is used for shapes and large numerals only; small red text uses #b3321a (5.3:1). Small text is never put on a vermilion fill.
- **Layout:** asymmetric. Masthead with a heavy top rule; the hero sentence with a vermilion bar; the lead line as a ledger strip with dashed dividers, a hazard-striped gate cell and an inverted "contacted" cell; a work-order task form (label left, field right); a job ticket for "now"; stamps for task status; a ledger table for leads; a typeset roster for the team; a hazard-striped rule over "Waiting for a person"; a staircase of six steps for the walkthrough.

## What each part shows (all existing information is kept)
- **Hero and ledger line:** same sentence and counts; the same chips (`Acme <em>87/100`) and `#email-1` links.
- **Map ("How the team is wired", new, inline SVG + SMIL + CSS, in `scripts/dashboard-art.mjs`):**
  - You, the coordinator as the hub, the nine specialists around it as tickets with a drawn glyph each, the evaluator as a double-framed checkpoint, and a person's gate (bust, stamp, striped barrier arm) before an "outside this folder" wall.
  - Lead chain: thick mustard arrows researcher, lead-generator, outreach, sales, demo-handler.
  - Backups: a hatched shadow behind each agent that has a `-fallback` file (read from `data.agents`; the coordinator has none, so it has no shadow).
  - Live data: task counts on each agent, requests on the hub, reviews on the evaluator, `found` and `qualified` on lead-generator, `drafted` on outreach, `contacted` on sales, and waiting sends at the gate.
  - **Demo loop (nothing running), 24 s on one shared SVG clock:** the task slip goes You to coordinator, then to outreach; a file rides the belt to the evaluator; the verdict plate flashes REVISE and a red token goes back to the coordinator and out again; the file rides again; PASS goes green to the gate and waits at the barrier; the stamp lands, YES prints, the arm lifts, then the token leaves. Each station's halo pulses as the token reaches it.
  - **Live mode (a run is alive):** the hub and the agent named in the latest step get a vermilion halo and a mustard fill; its spoke turns vermilion with a moving dot; agents reached earlier in the recent steps are tinted; an agent on its backup shows "BACKUP IN".
  - How agents are found: `activeAgents(steps, names)` reads the steps `recentSteps` already returns. "Handed work to X" names X; "Wrote outputs/<area>/" names the area's owner (research: researcher, outreach: outreach, sales, marketing, demos: demo-handler, docs: docs-handler, dev: developer, reviews: evaluator); `X-fallback` counts as X on its backup.
  - Below 1080 px the drawing is replaced by a vertical route list with the same counts and highlights.
- **"How the team works":** six steps with small SVG drawings: give a task, the coordinator hands it out, a specialist saves a file, the evaluator scores it (80 or more passes, at most 2 revisions), a backup steps in after 3 failures, a person says yes. They reveal in a stagger and animate when scrolled into view.
- **Everything else** (task box, now running, tasks, leads, team, waiting for a person, report/draft view, sign-in) is restyled. The sign-in page has a data-free lock-and-barrier picture and still has none of the words "Pippin", "leads", "approvals" or "jarvis".

## Live refresh
`renderLive` still returns two parts split by `<!--split-->`. The map is in the first part. The client no longer replaces it: `setTop` pulls the old `#map` out, writes the new first part, patches the old map from the new one (only `data-*` attributes and leaf text of parts that carry `data-k`), and puts the old map back. Animations therefore keep running across the 3 s refresh. `last` still skips the refresh when the HTML is unchanged. The task box and open `<details>` are untouched as before.

## Accessibility and motion
- SVG has `role="img"` and `aria-labelledby` (title and a long description). A live caption (`aria-live="polite"`) says what is working.
- `prefers-reduced-motion: reduce`: tokens, halos, verdict plates, stamp and arm animations are hidden (a static stamp and closed arm are shown instead); the walkthrough shows its final state; CSS animations are off. The diagram stays readable.
- A "Pause motion" button (shown only when JS runs, desktop layout) pauses SMIL and CSS motion. Focus rings are vermilion, 3 px.
- With JS off the page is fully server-rendered; the walkthrough is visible and the demo loop still plays (SMIL needs no script).

## Risks
- Fonts come from Google, as before. If blocked, fallbacks are Georgia, Arial Narrow/Impact and Consolas; layout holds but looks different.
- The map matches agent names exactly (`knowledge-base`, `demo-handler`...). A renamed agent would show no counts until the ring list in `dashboard-art.mjs` is updated.
- The `/live` response carries the map now, about 35 KB every 3 s on a local page (skipped client-side when unchanged).
