# Critical-signal override in the lead gate

## Problem

The gate's verdict is built from a list of reasons. Some reasons make it a Stop and some make it Conditional, and a lead with neither gets a Go. Three of our own "never contact" rules did not force a Stop:

- A competitor could not be recorded on a lead at all (no field), so it could only be caught by a person using `hold`.
- A personal (non-work) email address, which `knowledge/company.md` says never to contact, was not checked.
- A support-only inbox was only Conditional.

Also, the suppression match in the gate looked at the lead's own domain and the contact's full address only. An opt-out for `example.com` did not cover `asha@example.com` when the lead's website was on another domain, or a lead on `app.example.com`. Opt-outs are final (hard rule 7).

Root cause, from `scripts/leads.mjs` at HEAD `f08690e`: `gateOf` listed Stop reasons inline (lines 280-285), with no competitor or personal-mail test, and pushed `support-only inbox` into `conditional` (line 284). `suppressedBy` (starts at line 247) compares `s.value === domain || s.value === contact` only.

## Where the idea comes from

Rezvani `claude-skills`, `commercial/skills/deal-desk/SKILL.md` (MIT, "Copyright (c) 2025 Alireza Rezvani"). I read the raw file with curl on raw.githubusercontent.com on 2026-11-03 (WebFetch is not in my tool list). Line 73, under the Anti-patterns heading: "Skipping the redline scan because the score is high. A high composite with `UNCAPPED_INDEMNITY` is still a DECLINE — critical signals override composite." Line 14: "Never auto-approves." Only that principle is used. The signals are ours, and no code was copied (the source is Python and its signals are contract terms).

## Risks

- **False Stop on a personal email.** A solo founder who publishes only a Gmail address now shows Stop, where before they could be a Go. That is what company.md says, but it affects segment 1 (solo founders, memory 2026-11-01). The list is in `PERSONAL_MAIL`. A person should confirm the rule is meant for the gate and not only for cold email.
- **Support-only Stop** (item 1 above).
- **Wider suppression match in the gate.** If someone suppresses a very broad domain (a shared host such as `github.io` or `vercel.app`), every lead under it shows Stop in the gate. The import and set-status checks are not widened, so they still use the narrow match.
- **Profile-URL opt-outs over-block (revision 1).** `suppress <LinkedIn or X profile URL>` strips the path and stores `linkedin.com` (or `x.com`). With the wider match, every lead with a LinkedIn contact then shows Stop (the reviewer's probe: two LinkedIn leads both `Stop suppressed (linkedin.com)`). The real pipeline has one such lead each: Cool Analytics (LinkedIn) and SpaceWise (an `x.com` URL). On `main` the same entry blocks nothing, so a LinkedIn opt-out recorded by URL is silently not enforced there: a gap that already existed and breaks hard rule 7. I kept the over-block, because a visible Stop is the safe failure. Fixing `suppress` itself is a separate task (T-20261103-11). A test pins the current behaviour.
- **Three suppression matchers disagree (revision 1).** The gate (domain, parent domain, contact host); `suppressedBy` (exact lead domain or exact address: the at-once disqualify, import and `set-status`); and `scripts/send-email.mjs` `isSuppressed` (exact address or that address's exact domain). A lead caught only by the wider match, for example `asha@mail.optx.example` with `optx.example` suppressed, is a gate Stop, but `set-status ... drafted` still works and `isSuppressed` returns nothing for that address.
- **`PERSONAL_MAIL` is a short fixed list**, not a complete one. A personal address on another provider is not caught.
- **`competitor` is only as good as who sets it, and a wrong value can't be cleared (revision 1).** It is empty on every lead today. No command removes or corrects it: a re-import can only replace it with another non-empty value (an empty one is refused), and `guard.mjs` blocks agents from editing `pipeline/leads.jsonl`, so removal needs a person to edit the file. Use `hold` (which has `release`) while a competitor question is still open, and set `competitor` only once it is settled.
- The `competitor` field adds a key to the lead record shape. `check` and `export-csv` ignore unknown keys, and I saw no code that rejects them.
