## The bug

`node scripts/leads.mjs suppress https://www.linkedin.com/in/asha "<reason>"` printed `Suppressed linkedin.com.` and stored `{"value":"linkedin.com"}`. The same happened for X (`x.com`).

- On `main`: that entry matches no lead, so the person's opt-out is not enforced. They can still be drafted for and emailed. This breaks hard rule 7, and was already true before 09a.
- With the 09a gate (`92931ef`): the same entry stops every lead whose contact is on that host (in the real pipeline, Cool Analytics on LinkedIn and SpaceWise on an `x.com` URL).
- Three matchers disagreed about what an entry covers, so the same list gave different answers depending on the command.

## Root cause

`scripts/leads.mjs` at `92931ef`:
- Line 264, in `suppress`: `.replace(/\/.*$/, '')` removes everything after the host. A profile on a shared site cannot be told apart from the site.
- Line 257, `suppressedBy` (import, `set-status`, the at-once disqualify in `suppress`): exact lead domain or exact contact address only.
- Line 288, `suppressionHit` (gate only): also parent domains and the contact's host. This is what turned the bare `linkedin.com` entry into a site-wide block.
- `scripts/send-email.mjs` line 82, `isSuppressed`: exact address or that address's exact domain.

## The fix

One matcher, `suppressionMatch(list, { contact, website, domain })` in `scripts/_shared.mjs`. I could not put it in `leads.mjs` and import it from `send-email.mjs`: `leads.mjs` runs its command line at load (`switch (command)` at the bottom, no `isMain` guard), so importing it would exit with a usage error. The brief allowed `_shared.mjs` for this case.

An entry is one of:
- an email address: that address only;
- a company domain: the domain, its subdomains and addresses on them (label boundary, so `notexample.com` is not covered);
- a profile URL: that page and the pages below it.

A shared host is never a company domain. `SHARED_HOSTS` (in `_shared.mjs`, the list is `PROFILE_PATH_HOSTS` plus `PROFILE_SUBDOMAIN_HOSTS`): linkedin.com, x.com, twitter.com, github.com, gitlab.com, medium.com, substack.com, facebook.com, instagram.com, youtube.com, producthunt.com, peerlist.io, wellfound.com, threads.net, bsky.app, dev.to, and the subdomain hosts github.io, gitlab.io, vercel.app, netlify.app, pages.dev, hashnode.dev, notion.site, carrd.co, webflow.io, blogspot.com, wordpress.com (plus subdomains of medium.com and substack.com). I chose the extras beyond the seven the brief named; trim or extend the list in one place.

`suppress` (`classifySuppression`):
- Email: stored lower-case.
- A page on a shared host: stored as a normalised URL, the `https` scheme + lower-case host (no `www.`, `m.`, `mobile.`; LinkedIn country sites collapse to `linkedin.com`; `twitter.com` becomes `x.com`) + lower-case path, with no query, fragment or trailing slash. Example: `HTTPS://www.LinkedIn.com/in/Asha-A/?utm=x#top` is stored as `https://linkedin.com/in/asha-a`. `https://asha-page.github.io/` is stored as `https://asha-page.github.io`.
- A bare shared host (`linkedin.com`, `https://www.linkedin.com/`, `github.io`, ...): refused with exit 1: "linkedin.com is a shared site: suppressing it would cover everyone who has a page there. Give the person's profile URL instead, for example https://linkedin.com/in/<name>". The refusal happens before the lock and before any write.
- `https://linkedin.com/in` (one path segment) is also refused, because a profile-URL entry matches the pages below it and `/in` would cover every member. LinkedIn needs two segments (`in/asha`, `company/acme`).
- Anything else: a domain, as before.

Old entries: a bare shared-host entry (`isBareSharedHostEntry`) matches nothing, and `node scripts/leads.mjs check` prints `WARNING: ... re-enter the person as a profile URL` to stderr for each. It does not fail the check (exit stays 0). There is no `pipeline/suppression.jsonl` yet, so nothing real is affected.

## Risks

- **Wider matching everywhere.** Import, `set-status` and `suppress` now use the gate's wider match. A company-domain opt-out for `example.com` now also disqualifies a lead whose contact is `x@mail.example.com`, or whose website is a subdomain. That is the point of an opt-out, but it can surprise someone.
- **A profile URL cannot block an email.** `https://linkedin.com/in/asha` stops a lead with that LinkedIn contact. If the same person also has an email contact, or is emailed by a different lead, that needs its own entry. `send-email.mjs` only sees an address, so a LinkedIn-only entry cannot stop an email to the same person. Record both where both exist.
- **Prefix matching.** A profile-URL entry covers the pages below it (`github.com/acme` covers `github.com/acme/repo`), on a `/` boundary only. The brief said "exact profile URL"; I chose boundary prefix so a profile's sub-pages (`/details/...`) cannot slip past. `asha-a` does not cover `asha-ab` (tested).
- **Lower-case paths.** The stored path is lower-case. LinkedIn, X and GitHub handles are case-insensitive, so this is right for them; on a host with case-sensitive paths it could match another page that differs only by case, which fails safe (over-blocks).
- **Shared-host list is a judgement.** A site not in `SHARED_HOSTS` is treated as a company domain, so `suppress somehost.example` would cover everyone on it. A new shared site (a new link-in-bio service) needs adding to the list. Personal mail domains such as `gmail.com` are not on it: a bare `gmail.com` entry would still match every Gmail address (the gate already Stops those). Say so if you want it refused too.
- **Subdomain-tenant sites** (`asha.github.io`) are stored as URL entries, not domain entries. An old-format `asha.github.io` domain entry still works (it is not bare), so no migration is needed there.
- **Hand-written entries** must use the same forms. A value with a `/` is read as a URL and normalised at match time, so a hand-written `linkedin.com/in/asha` also works.
- **Warning goes to stderr** and does not fail `check`, so a script that only reads the exit code will not see it.
- The dashboard flake above could look like a regression from this change; it is not.
