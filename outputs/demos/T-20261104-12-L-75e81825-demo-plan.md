### The open problem: can our trial read Deplexo's public repo?

**What the fact sheet settles.** FS 85 lists two ways to add a repository: install the GitHub App, or paste a public repository URL. FS 130 says the GitHub App gives read-only access to repositories, and the README it cites (lines 74-79) describes the webhook. The App route needs the repository's owner to install it, so it does not work for `Deplexo/cli` with our accounts. The paste route is a separate route. FS 85 does not say the pasted repo must belong to the user.

**What the code and live site say (not in the fact sheet).**
- The live homepage FAQ says "Public repositories can also be added by pasting their link" (read 2026-11-04).
- `repos/motionrepo/docs/architecture.md:103` says pasting a URL works for public repositories only, checked with GitHub without a token.
- `src/git/repositoryImportService.ts` `assertUserMayImport` on `main`: a user may import a repository on an account where they installed the App; otherwise the check asks GitHub, without a token, whether the repository is public. This is the code rule behind the paste route.

So the likely answer is yes via the paste route. Grade: supported with effort, not yet seen live (code rule: `assertUserMayImport`). I did not sign in to the dashboard (no credentials by design), so I have not seen it work on a third party's repo. The dry run settles it. The trial also allows 1 repository (FS 107), and I could not find whether removing a repo frees the slot.
